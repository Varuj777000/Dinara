# Маркетплейс автозапчастей — рабочие заметки

Проект ведёт один разработчик (Claude). Владелец — действующий магазин запчастей,
код не читает. Всё, что он должен проверить, сводится к одной команде и одному
экрану в браузере.

## Команды

```bash
npm run dev                   # сайт на http://localhost:3000
npm run build                 # прод-сборка Next (заодно ловит ошибки типов в app/ и lib/)
npm run lint                  # eslint
npm run db:push               # применить схему Prisma к SQLite
npm run db:studio             # посмотреть содержимое базы глазами
npm run import                # импорт data/tiko.xlsx в магазин "Тико"
npm run demo:shops            # виртуальные магазины для проверки экрана сравнения
npm run demo:shops -- --clear # убрать их
```

Тестов в проекте нет.

Полный перезапуск с нуля: удалить `prisma/dev.db`, затем `db:push`, `import`, `demo:shops`.

## Особенности окружения, на которые уже потрачено время

- **npm ставит `prisma@8.0.0-rc` по тегу latest.** Версии CLI и клиента
  зафиксированы точно (`7.10.0`) через `--save-exact`; не обновлять их врозь.
- **`npm install` падает с `Cannot read properties of null (reading 'edgesOut')`** —
  баг арбориста npm 10.9.3 на этом дереве peer-зависимостей. Ставить с
  `--legacy-peer-deps`.
- **Prisma 7 не читает URL базы из `schema.prisma`.** Подключение задаётся в
  `prisma.config.ts` (и `datasource.url`, и `adapter` — нужны оба), клиент
  создаётся только с драйверным адаптером. Генерируемый клиент лежит в
  `generated/prisma`, импорт — из `@/generated/prisma/client`.
- Экспорт адаптера называется **`PrismaBetterSqlite3`**, а не `...SQLite3`.
- `npm audit` показывает уязвимости в `mysql2` и `deepmerge-ts` (они внутри
  Prisma CLI, MySQL мы не используем) и в `uuid` внутри `exceljs`. В веб-контур
  ничего из этого не попадает; `npm audit fix --force` откатил бы Prisma до 6 и
  ExcelJS до 3 — делать этого нельзя. Пересмотреть перед публикацией сайта.
- **Next 16 — свежий мажор, за пределами обучающих данных модели.** `next dev`
  сам поддерживает `AGENTS.md` в корне с предупреждением об этом; при
  сомнениях в API или файловой структуре сверяться с `node_modules/next/dist/docs/`,
  а не с тем, что «обычно» так в Next.js.

## Что это за продукт

Лид-модель: покупатель ищет деталь по артикулу, сравнивает цены и наличие
нескольких магазинов и связывается с выбранным. Платформа зарабатывает на
подписке магазинов, деньги покупателя через себя не проводит. Корзины, оплаты
и комиссии в текущем объёме нет.

## Решения, принятые владельцем

- Покупателю показывается цена из колонки **ZZAP** (розничная). Колонка ОПТ
  импортируется, но не отображается.
- Колонка **Закуп** (закупочная цена) **не импортируется вообще** — не должна
  существовать в базе, чтобы неоткуда было утечь. См. `FORBIDDEN` в `lib/columns.ts`.
- Дубли строк прайса по одному артикулу **схлопываются**: остаток суммируется,
  цена берётся минимальная ненулевая, складские ячейки собираются в список
  (виден только магазину).
- Остатки в прайсе ведутся вручную и не всегда точны, поэтому покупателю
  показывается «в наличии / под заказ» **без конкретной цифры**.
- Источник прайса — Excel, который владелец ведёт руками. Значит ведущие нули в
  числовых артикулах потеряны безвозвратно; такие товары помечены
  `Product.numericSource`.

## Архитектурные правила, которые нельзя нарушать

1. **Ключ товара — пара (бренд, нормализованный артикул).** Наименование товара
   никогда не участвует в сопоставлении: в реальном прайсе одна деталь называется
   по-разному даже внутри одного файла.
2. **Строка без бренда не публикуется.** Один и тот же номер встречается у разных
   производителей — склейка по голому артикулу покажет неверную цену на неверную
   деталь. Такие строки уходят в `QuarantineRow`.
3. **Никакого подбора по совместимости с автомобилем без лицензионных данных.**
   Ни VIN, ни марка-модель, ни «похоже, подойдёт». Ошибка в фитменте — это
   небезопасный ремонт, а не неудачная рекомендация. LLM тут использовать нельзя.
   Владелец подтвердил (2026-09-28): когда лицензионные данные о фитменте
   появятся, нужен полноценный подбор — марка, модель, год, кузов, двигатель,
   модификация, — а не урезанный вариант. До тех пор единственная временная
   замена — фильтр каталога по бренду (`getCategoryBrandFacets` в
   `lib/search.ts`, страница `/category/[slug]`): он просто сужает список по
   уже показанному атрибуту товара и не утверждает, что деталь подходит к
   конкретной машине.
4. **Прайс — полный снимок, а не дельта.** Импорт заменяет все предложения
   магазина целиком, иначе исчезнувшие позиции вечно висят «в наличии».
5. **Неоплаченная подписка скрывает предложения, но не удаляет данные** —
   `Shop.status` переключается в `suspended`, восстановление в один шаг.
6. Цены хранятся в **копейках** (`Int`), чтобы не ловить ошибки округления.

## Дизайн

Сайт называется **Dinara** (логотип — буква «D» с шестерёнкой, `components/Logo.tsx`,
иконка вкладки `app/icon.svg`). Палитра графит + оранжевый, шрифты Manrope (текст),
Unbounded (заголовки), Geist Mono (артикулы).

- Стили — обычные CSS-классы в `app/globals.css`, а не Tailwind-утилиты. Цвета
  только через токены (`--accent`, `--surface`, …); тёмная тема переопределяет их
  под `[data-theme="dark"]`. Tailwind подключён, `text-brand`/`bg-accent` и т.п.
  сопоставлены с новыми токенами.
- Скрипт в `<head>` (`app/layout.tsx`) до отрисовки ставит тему, класс `js` и
  пропуск прелоадера, если он уже показывался в этой сессии; поэтому у `<html>`
  стоит `suppressHydrationWarning`.
- Элементы с `data-reveal` без JS видны сразу (прячутся только под `.js`), их
  проявляет `SiteEffects`. Для списков — CSS-класс `rise` со ступенчатой
  задержкой через `--d`.
- Поиск — `next/form` с `action="/"`, переход без полной перезагрузки. На главной
  шапка поиск не показывает (он есть в первом экране). Скелетоны `loading.tsx`
  есть только у категории и детали: корневой `loading.tsx` прятал бы первый экран
  главной при каждом поиске.
- Витрина следует правилам выше: ни корзины, ни подбора по авто, ни выдуманных
  рейтингов/скидок/доставки. Все цифры на главной — из `getStats()`.
- Скриншоты для проверки: `npx playwright@1 screenshot --channel msedge
  --wait-for-timeout 3500 <url> <файл>` (установленный Edge, без скачивания
  браузера). Headless-скриншоты самого Edge снимают кадр до ухода прелоадера.

## Деплой на Vercel (демо-хостинг)

Живая демо-ссылка: **https://dinara-delta.vercel.app** (проект `varuj/dinara`).
База там — read-only копия `prisma/deploy.db`, реальный магазин «Тико»
переключён в `Shop.status = "suspended"` (данные целы, просто не публикуются),
видны только демо-магазины со случайными ценами. Это временный демо-хостинг,
не прод: см. «Известные ограничения» про переезд на Postgres.

Команда для повторного деплоя:
```bash
npx vercel deploy --yes --prod --project dinara \
  -b DATABASE_URL=file:./prisma/deploy.db \
  -e DATABASE_URL=file:./prisma/deploy.db \
  -e SQLITE_READONLY=1
```
Перед этим обновить `prisma/deploy.db` копией `dev.db` и заново
приостановить в ней немодемные магазины — иначе уйдут старые данные.

Грабли, на которые уже наступили:

- **Новый проект Vercel создался с `framework: null`.** Так вышло, потому что
  проект был предварительно создан через `vercel project add` — это пропускает
  автоопределение фреймворка. Без этого Vercel собирает сайт через
  `@vercel/static-build` (как обычную статику) вместо билдера Next.js, и вообще
  не создаёт serverless-функции — сайт становится сплошным 404, даже
  `/icon.svg`. Чинится: `vercel api -X PATCH /v9/projects/dinara -F framework=nextjs`,
  затем `vercel pull` (или новый `vercel deploy`, чтобы обновить локальный
  кэш настроек в `.vercel/project.json`).
- **Новый проект по умолчанию требует логин Vercel для просмотра любого
  деплоя** (`ssoProtection`). Отключается через API:
  `vercel api -X PATCH /v9/projects/dinara -F ssoProtection=null`.
- **SQLite-файл не попадает в собранную функцию сам по себе.** Next.js
  трассирует только файлы, до которых дотянулся через `import`/`require`; путь
  из `DATABASE_URL` он не видит. Без явного указания — в рантайме ошибка
  `Cannot open database because the directory does not exist`. Решение — в
  `next.config.ts`: `outputFileTracingIncludes: { "/**": ["./prisma/*.db"] }`.
- **На read-only файловой системе Vercel SQLite не может создать
  journal-файл даже для SELECT.** Нужен явный `readonly: true` у адаптера —
  включается переменной `SQLITE_READONLY=1` (см. `lib/db.ts`).
- **Symlink-ошибка при локальном `vercel build` на Windows**
  (`EPERM: operation not permitted, symlink ...`) — Windows без включённого
  Developer Mode / прав администратора не даёт создавать symlink, которые
  билдер Next.js использует для дедупликации функций. На это можно не
  обращать внимания: деплой всё равно собирается удалённо на Linux-машине
  Vercel через обычный `vercel deploy` (без `--prebuilt`).
- **Next.js 16 по умолчанию собирает прод-билд через Turbopack**, и в момент
  подключения этого проекта он не проходит этап «Collecting build traces» —
  трассировка файлов для serverless-функций. Это не оказалось финальной
  причиной проблемы (настоящая — framework: null, выше), но если трассировка
  снова пропадёт из локального `next build`, форсировать Webpack можно
  флагом `next build --webpack`.
- Имя проекта Vercel обязано быть в нижнем регистре — «Dinara» (как называется
  папка) не проходит валидацию, только «dinara».

## Известные ограничения текущего состояния

- База — SQLite. Перед первым настоящим сторонним магазином нужен переезд на
  PostgreSQL: меняется `provider` в `schema.prisma` и адаптер в
  `prisma.config.ts` и `lib/db.ts`; модели и запросы остаются прежними.
- Кабинета магазина и админки ещё нет: магазины и импорт заводятся из терминала.
- Кнопка «Позвонить» на карточке детали — это `tel:`-ссылка на `Shop.phone`;
  если у магазина телефона нет, вместо кнопки показывается «Телефон
  уточняется». Настоящей формы заявки/чата всё ещё нет.
- Контакты платформы (WhatsApp, Telegram, город) в `lib/contacts.ts` —
  **временная заглушка**, попросил владелец, чтобы увидеть сайт целиком.
  Заменить на настоящие данные перед показом сайта живым покупателям.
- Справочник в `lib/brand-groups.ts` требует проверки владельцем: группы вроде
  VAG и Hyundai / KIA склеивают несколько марок в один бренд.
- Категорий как модели в базе нет: `/category/[slug]` — это поиск по ключевому
  слову в `Product.nameLower` (см. `lib/categories.tsx`), а не настоящая
  таксономия. Фильтр по бренду на этой странице — тоже не подбор по авто,
  см. правило 3 выше.

## Что уже проверено на реальных данных

Прайс `data/tiko.xlsx` (16 187 строк, 8 396 заполненных) импортируется в
7 778 позиций: 188 схлопнуто из нескольких строк, 432 в карантине
(221 без цены, 198 без бренда, 13 без артикула), 588 брендов из 596 написаний,
2 227 артикулов пришли из числовых ячеек и помечены `numericSource`.

Проверены все три режима поиска: точный артикул (`GDB2372`), префикс (`GDB23`),
наименование (`свеча зажигания`), пустой результат и схлопнутый дубль
(`04893700AA`, был двумя строками по 4 500 и 5 000 ₽).
